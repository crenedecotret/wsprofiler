# Plan: Wire Optimisation Option into Main Wizard

## Overview
Replace the standalone "Two-Step Profile Wizard" with a new "Optimise" step inside the main 3-step wizard. The Optimise step reuses the two-step wizard's second-half logic (generate add-on chart → measure → combine → build profile) and supports multiple optimisation passes. Save states (`.wsp`) are extended to store profile/generate settings and per-pass file data.

## Key Design Decisions
- **Optimise is a 4th page** in the main wizard sidebar, not a modal dialog.
- **Two-Step button removed** from `Wizard`; its logic is absorbed into `OptimisePage`.
- **Embedded MeasurementPage** inside `OptimisePage` (same pattern as `TwoStepWizardDialog`).
- **`.wsp` format extended** (version bump to 2) to store `generate_config`, `profile_configs`, and optimisation pass file roles.
- **Backward compatibility**: old v1 `.wsp` files load as a single original pass with no optimisation data.
- **Patch generation** reuses the existing two-step approach (`targen -c precond.icc`) for consistency; `pass2_generator.py` can be swapped in later without changing architecture.
- **Filename convention**: each optimisation pass gets an auto-incremented suffix to avoid overwriting previous files. Pass N files are named `<target>_opt<N>.ti2`, `<target>_opt<N>.icc`, and combined files as `<target>_combined<N>.ti3`.

## Files to Modify / Create

### 1. Session Format (`wsprofiler/session.py`)
**Changes:**
- Bump `CURRENT_VERSION` to `2`.
- Add `WIZARD_TYPE_OPTIMISED = "optimised"`.
- Extend `SimpleSnapshot` with optional fields:
  - `generate_config: dict[str, Any]` — instrument, paper, pages, target_path, double_density, no_border
  - `profile_configs: list[dict[str, Any]]` — one per pass (original + each optimisation). Each dict has `gamut_profile`, `quality`, `smoothing`, `description`.
  - `optimisation_count: int = 0` — number of completed optimisation passes.
- Add `_dict_to_simple_snapshot()` helper that handles both v1 (no extra fields) and v2.
- `load_archive()` stays generic; callers handle version-specific fields.

### 2. Session Controller (`wsprofiler/ui/session_controller.py`)
**Changes:**
- `SimpleSessionController.save()` accepts optional `generate_config` and `profile_configs` and packs them into the snapshot.
- `SimpleSessionController.load()` returns the raw manifest dict (already does) so `OptimisePage` can read the new fields.
- Remove `SessionController` and `TwoStepWizardDialog` references if no longer needed (or keep for backward compatibility loading `.wsp2`).

### 3. Profile Page (`wsprofiler/ui/pages/profile_page.py`)
**Changes:**
- Add a new signal or extend `profileGenerated` to include settings:
  - Option A: Change `profileGenerated = Signal(Path, dict)` where dict contains current settings.
  - Option B: Add `get_profile_config() -> dict` method that `Wizard` calls after generation.
  - **Recommended: Option B** (minimal change to existing signal consumers).
- `get_profile_config()` returns `{"gamut_profile": str|None, "quality": str, "smoothing": float, "description": str}`.

### 4. Wizard (`wsprofiler/ui/wizard.py`)
**Changes:**
- Remove `two_step_btn` and `_open_two_step_wizard()`.
- Add `OptimisePage` as the 4th step in `_pages` and sidebar.
- Track internal state after profile generation:
  - `self._last_profile_config: dict | None = None`
  - `self._last_generate_config: dict | None = None`
- `_on_profile_generated(icc_path)`:
  - Capture `generate_config` from `GeneratePage` (add a `get_generate_config()` method there).
  - Capture `profile_config` from `ProfilePage.get_profile_config()`.
  - Pass both configs to `OptimisePage.set_original_pass_data(...)` so it is immediately usable.
  - Include configs in the `.wsp` save call.
- `_on_step_changed`: when navigating to Optimise, notify it of current data availability.

### 5. Generate Page (`wsprofiler/ui/pages/generate_page.py`)
**Changes:**
- Add `get_generate_config() -> dict` returning current generate settings (`device`, `paper`, `pages`, `target_path`, `double_density`, `no_border`).

### 6. Optimise Page — NEW (`wsprofiler/ui/pages/optimise_page.py`)
**Responsibilities:**
- Display load/generate/measure/build UI for optimisation passes.
- Internally uses a `QStackedWidget` with sub-pages:
  - `STATE_NO_DATA`: message + "Load .WSP Session" button.
  - `STATE_READY`: shows current pass summary + "Generate Add-on Chart" button.
  - `STATE_GENERATING`: progress label + console while `targen`/`printtarg` run.
  - `STATE_MEASURE`: embedded `MeasurementPage` for reading the add-on chart.
  - `STATE_BUILDING`: progress label + console while combining TI3s and running `colprof`.
  - `STATE_DONE`: shows final ICC path + "Optimise Again" button.

**Key attributes:**
- `self._workspace: Path`
- `self._original_pass: dict` — ti1, ti2, ti3, icc paths + generate_config
- `self._optimisation_passes: list[dict]` — each with ti1, ti2, ti3, icc
- `self._combined_ti3s: list[Path]` — one per optimisation pass
- `self._profile_configs: list[dict]` — profile settings for each pass
- `self._current_pass: int` — 0 = original, 1+ = optimisation passes
- `self._measure_page: MeasurementPage` — embedded widget

**Key methods:**
- `set_original_pass_data(generate_config, profile_config, files)` — called by Wizard when a profile is just completed.
- `load_wsp_session(wsp_path)` — uses `SimpleSessionController.load()` to restore state.
- `_start_add_on_generation()` — runs `targen -c <latest_icc>` + `printtarg` via `QProcess` (reuse logic from `TwoStepWizardDialog._run_auto1()` chart-2 generation part).
  - Target name for pass N: `<original_target>_opt<N>`.
  - Example: original `mytarget` → pass 1 chart = `mytarget_opt1.ti2`.
- `_on_measurements_complete(ti3_path)` — stores pass ti3 (named `mytarget_opt1.ti3`), advances to BUILDING.
- `_run_build_profile()` — combines all TI3s into `<target>_combined<N>.ti3`, then runs `colprof` with saved profile settings to produce `<target>_opt<N>.icc`.
- `snapshot() -> dict` / `apply_snapshot(dict)` — for saving/loading .wsp.

**Signals:**
- `optimisationComplete = Signal(Path)` — emitted when a pass finishes, with the ICC path.

### 7. TI3 Combiner (`wsprofiler/ti/ti3_combiner.py`)

## Data Flow

### Saving (after original profile)
```
ProfilePage.profileGenerated(icc_path)
  → Wizard._on_profile_generated()
    → gather generate_config + profile_config
    → OptimisePage.set_original_pass_data(configs, files)
    → SimpleSessionController.save(
         workspace, target_name, file_paths,
         generate_config=..., profile_configs=[...]
      )
```

### Saving (after optimisation pass)
```
OptimisePage._run_build_profile() success
  → update internal pass list
  → SimpleSessionController.save(
      workspace, target_name, file_paths_with_pass_roles,
      generate_config=..., profile_configs=[...],
      optimisation_count=N
    )
```

### Loading
```
User clicks "Load .WSP" in OptimisePage
  → SimpleSessionController.load(path)
  → manifest dict returned
  → OptimisePage.apply_snapshot(manifest)
    → restore original_pass + optimisation_passes + configs
```

## Filename Convention for Optimisation Passes

To prevent collisions and make passes identifiable on disk, each pass uses an auto-incremented `_opt<N>` suffix derived from the original target stem.

| Pass | `.ti1` | `.ti2` | `.ti3` | `.icc` | Combined `.ti3` |
|---|---|---|---|---|---|
| Original | `mytarget.ti1` | `mytarget.ti2` | `mytarget.ti3` | `mytarget.icc` | — |
| Pass 1 | `mytarget_opt1.ti1` | `mytarget_opt1.ti2` | `mytarget_opt1.ti3` | `mytarget_opt1.icc` | `mytarget_combined1.ti3` |
| Pass 2 | `mytarget_opt2.ti1` | `mytarget_opt2.ti2` | `mytarget_opt2.ti3` | `mytarget_opt2.icc` | `mytarget_combined2.ti3` |
| Pass N | `mytarget_optN.ti1` | `mytarget_optN.ti2` | `mytarget_optN.ti3` | `mytarget_optN.icc` | `mytarget_combinedN.ti3` |

The `.wsp` archive maps these on-disk names to role keys (`pass1_ti2`, `pass1_icc`, `combined1_ti3`, etc.).

---

Original pass (always present):
- `ti1`, `ti2`, `ti3`, `icc`
- `tiff_1`, `tiff_2`, ...

Optimisation pass N (N starting at 1):
- `pass{N}_ti1`, `pass{N}_ti2`, `pass{N}_ti3`
- `pass{N}_tiff_1`, ...
- `pass{N}_icc`
- `combined{N}_ti3` (combined original + passes 1..N)
