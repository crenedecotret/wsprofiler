# Plan: Fix wizard-completion and WSP-session-integrity bugs

## Scope

The user asked for bugs that block going through the wizard or that corrupt a saved `.wsp` session. Three confirmed, high-impact bugs surfaced after auditing the wizard flow, the session save/load path, and the chartread/measurement page. This plan fixes those three. Lower-impact / speculative findings (xicclu output parsing, Windows `WindowsProcessRunner`, duplicate CTI1 density rows, `_dict_to_simple_snapshot` dropping `measurement_complete`, `load_archive` no version check) are listed at the bottom as **out of scope** for this change — to be tackled separately.

All three fixes are small, surgical edits in two files. No data-format migration is needed; existing `.wsp` archives remain valid.

---

## BUG 1 — CRITICAL: `save_session_state()` wipes the ICC and all profile/optimisation data from the WSP

### Verified root cause

`Wizard.save_session_state()` (`wsprofiler/ui/wizard.py:399-411`) is called from three places:

1. `MainWindow.closeEvent` (`wsprofiler/ui/main_window.py:42-43`) — fires on **every** app close
2. `Wizard._on_measurement_stopped` (`wizard.py:336-338`) — fires whenever chartread exits
3. `Wizard._on_step_changed` (`wizard.py:564-566`) — fires when the user navigates **away** from the Measure page (index 1)

It does two damaging things:

- It calls `_collect_workspace_files()` (`wizard.py:413-430`), which only collects `.ti1/.ti2/.ti3/.tiff*` — **never the `.icc`**, even though one exists in the temp dir after profiling.
- It hard-codes `profile_configs=[]` and `optimisation_count=0`.

So once the user has generated a profile (or completed optimisation), any of those three triggers overwrites the `.wsp` with a snapshot that has **no `icc` role, no profile configs, and no optimisation passes**. Reloading the WSP lands the wizard on the Profile step with Optimise disabled — all post-profile work is lost.

### Reproducer (manual)

1. Generate → Measure → Profile (ICC produced, `optimisation_count=0` saved with ICC).
2. Click "Measure" in the sidebar, then "Profile" again. `_on_step_changed` fires `save_session_state` going **to** Profile because `_prev_step_index == 1`.
3. Close the app → `closeEvent` fires `save_session_state` again.
4. Reopen → load the session. Optimise step is disabled; ICC is gone from the archive.

### Fix

Rewrite `save_session_state()` to capture the **current** full session state instead of a degraded "measure-only" snapshot. Concretely:

- Collect files via the existing richer collectors:
  - If `OptimisePage.has_data()` is true → use `_collect_optimisation_files(opt_page)` (already includes icc + all `pass{i}_*` + `combined{i}_ti3`).
  - Else if a `.icc` exists at `self._session.target_path.with_suffix(".icc")` (profile produced but Optimise page not yet wired) → use `_collect_session_files(include_icc=<that icc path>)`.
  - Else → current `_collect_workspace_files()` behaviour (pre-profile steps).
- Source metadata from the live pages instead of hard-coding:
  - `profile_configs`: if Optimise page has data → `opt_page._profile_configs`; elif a profile config is known on the Profile page → `[prof_page.get_profile_config()]`; else `[]`.
  - `optimisation_count`: `len(opt_page._optimisation_passes)` if Optimise page has data, else `0`.
  - `measurement_complete`: keep current `self._measurement_complete`.
  - `generate_config`: keep `gen_page.get_generate_config()`.

Net effect: `save_session_state()` becomes a faithful "snapshot current state" save, identical in shape to `_on_profile_generated` / `_on_optimisation_complete`. The three trigger sites (close, chartread exit, leaving Measure page) then preserve ICC + profile configs + optimisation data instead of destroying them.

### Files to modify

- `wsprofiler/ui/wizard.py` — rewrite `save_session_state` (lines 399-411). `_collect_workspace_files` can stay (still useful as the pre-profile branch) or be folded in; minimal change preferred.
- No change to `main_window.py`, `session_manager.py`, or `session.py`.

## BUG 2 — HIGH: Fresh-measurement `measurementsComplete` signal is emitted only via a fragile fallback, so a ti3 parse error strands the user on the Measure page

### Verified root cause

`MeasurementPage._on_finished` (`wsprofiler/ui/pages/measurement_page.py:499-532`) does:

```python
if code == 0 and self._current_ti3_path:             # line 504
    self.measurementsComplete.emit(self._current_ti3_path)   # DEAD on fresh measurement
...
if self._current_chart_path:
    ti3_path = self._current_chart_path.with_suffix(".ti3")
    if ti3_path.exists():
        self._load_existing_ti3(ti3_path)           # line 517 — emits via side effect at line 244
```

`_current_ti3_path` is only ever set inside `_load_existing_ti3` (line 243), so on a **fresh** measurement (no pre-existing `.ti3`) the dedicated emit at line 505 is dead. Completion is signalled only as a side effect of the visual-refresh call at line 517 → 244.

If `_load_existing_ti3` raises (partial ti3 written by chartread, multi-line DATA_FORMAT parser quirk in `ti3.py:69-73`, etc.) the `except` at line 248 swallows it, the side-effect emit never fires, and `_on_finished` only emits `measurementStopped` (line 532). The wizard saves a no-ti3 WSP and leaves the user stuck on the Measure page with no completion dialog and no path to Profile.

### Fix

Make the completion emission explicit and not depend on `_load_existing_ti3`'s side effects:

1. At the top of `_on_finished`, after stopping the watcher, compute `ti3_path = self._current_chart_path.with_suffix(".ti3") if self._current_chart_path else None`.
2. If `code == 0 and ti3_path is not None and ti3_path.exists()`:
   - set `self._current_ti3_path = ti3_path`
   - emit `self.measurementsComplete.emit(ti3_path)` exactly **once**
3. Add an internal flag/parameter to `_load_existing_ti3` (e.g. `_load_existing_ti3(ti3_path, emit_complete: bool = True)`) and call it with `emit_complete=False` from `_on_finished`'s visual-refresh path (line 517) so it no longer double-emits. Keep the default `True` for the resume path (`_load_file` line 214) so existing behaviour for "open a WSP with ti3" is unchanged.
4. Guard the line-244 emit with that flag.

Net effect: completion is signalled deterministically whenever chartread exits 0 with a `.ti3` on disk, independent of ti3 parse success. The visual refresh still runs best-effort and failures stay logged to the console.

### Files to modify

- `wsprofiler/ui/pages/measurement_page.py` — restructure top of `_on_finished` (lines 499-519); add `emit_complete` param to `_load_existing_ti3` (lines 218, 244).

## BUG 3 — MEDIUM: Preconditioning ICC is not bundled into the WSP for reference

### Verified root cause

`GeneratePage.get_generate_config()` (`wsprofiler/ui/pages/generate_page.py:437-451`) does **not** record the preconditioning profile path, and no save path includes the precond ICC file in `file_paths`. So a user who picks a precond ICC on the Generate page gets a `.wsp` archive that has no trace of which precond profile was used — the session is not self-contained.

`Wizard.load_wsp_session` line 194 (`precond_path = ... if False else None`) reflects the right call: the chart has **already been generated** by the time the WSP is loaded, so there is no functional reason to restore the precond field on the Generate page. The precond ICC's value in the saved file is **reference/traceability** only.

### Fix

Goal: bundle the precond ICC into the `.wsp` archive as a file entry so the saved session is self-contained and the precond profile is recoverable later. Do **not** restore it to the Generate UI on load.

1. Add `"precond_path": <current precond path widget text>` to the dict returned by `GeneratePage.get_generate_config()`. This records which precond was used in the manifest (role name lookup on load).
2. In every post-Generate auto-save path that builds `file_paths`, include the precond ICC if it points to an existing file:
   - `_auto_save_after_generate` (wizard.py:441)
   - `save_session_state` (the rewrite from BUG 1)
   - `_auto_save_after_measure` (wizard.py:464)
   - `_collect_session_files` (wizard.py:491)
   - `_collect_optimisation_files` (wizard.py:517) — only the original-pass precond, sourced from `opt_page._generate_config["precond_path"]`
   Add `file_paths["precond_icc"] = Path(precond_path)` when the path is non-empty and the file exists. `save_session` (session.py:182-191) already handles files outside `base_dir` by falling back to a flat arcname (the file's basename), so an external system ICC gets bundled correctly.
3. Leave `Wizard.load_wsp_session` (line 191-196) as restoring `precond_path=None` to the Generate UI — but optionally log the bundled precond role to the console (e.g. "Preconditioning profile used: <name>") for reference. Simplify the `if False else None` to a plain `None` for clarity.

The user has explicitly confirmed: precond ICC **must** be saved in the WSP for reference, but does **not** need to be restored to the Generate UI.

### Files to modify

- `wsprofiler/ui/pages/generate_page.py` — extend `get_generate_config()` return dict with `precond_path`. (Grep `generate_page.py` first to confirm the widget name holding the precond path; the plan assumes `precond_edit` based on convention.)
- `wsprofiler/ui/wizard.py` — add `precond_icc` inclusion to the four `file_paths` builders, and simplify the `load_wsp_session` restore line.
