# Plan: Replace targen with pass2_generator for Optimisation Charts

## Context

The current OptimisePage generates add-on charts by calling Argyll targen -c precond.icc -N0.75. The intended design is to use the greedy patch selector in pass2_generator.py. This plan wires generate_pass2_ti1() into OptimisePage, runs it synchronously, and shrinks the candidate pool so 672 patches finish in under 60 seconds.

## Timing Benchmark (real printer profile)

Tested with the R2000OC printer profile and a 500-patch synthetic .ti3:

| target_n | Time (old defaults) |
|----------|---------------------|
| 100      | ~3 s                |
| 200      | ~9 s                |
| 400      | ~34 s               |
| 672      | ~102 s              |

With the reduced candidate pool below, time should drop to ~20-30 s for 672 patches.

## Root Cause of Slowness

The greedy loop computes a candidates x selected distance matrix every iteration. With ~10,000 candidates and ~300 average selected patches, each iteration allocates an ~80 MB temporary array. Over 672 iterations this shuffles gigabytes through memory.

## 2. wsprofiler/profiling/pass2_generator.py

### 2a. Reduce default candidate pool

The initial profile already provides good grid coverage; the add-on chart only needs to reinforce weak areas. Reduce defaults in generate_pass2_ti1:

| Parameter | Old default | New default | Rationale |
|-----------|-------------|-------------|-----------|
| grid      | 17          | 6           | 6^3 = 216; initial pass already sampled densely |
| halton_n  | 4096        | 1024        | Still fills gaps with low-discrepancy coverage |
| neutrals  | 65          | 33          | 33 x 7 = 231; neutrals are critical |
| edge_steps| 33          | 17          | 10 x 17 = 170; edges still well-covered |

Resulting pool: ~216 + ~1024 + ~231 + ~170 + ~240 + ~32 = ~1,900 candidates (vs ~10,000). A 5x reduction in candidates directly translates to a 5x speedup in the greedy loop.

### 2b. Micro-optimise the eligibility gate

In select_patches, lines 560-565:

- Skip sqrt - compare squared distances against min_dE ** 2 instead of sqrt(...).
- Chunk selected-patch matrix - process selected patches in chunks of 64 instead of one giant broadcast. This keeps arrays in cache and avoids huge allocation churn.

### 2c. Add progress_callback

Add optional parameter to generate_pass2_ti1:

    progress_callback: Callable[[str, int, int], None] | None = None

The callback receives (stage_label, current_step, total_steps). Emit at 5 fixed stages (total = 5):
1. Building candidate pool
2. Predicting candidate colours
3. Loading pass-1 measurements
4. Selecting patches
5. Writing chart file

Default behaviour unchanged - existing callers that omit the parameter see no difference.

## 3. wsprofiler/ui/pages/optimise_page.py

### 3a. UI Changes - Patch Count Control

In _setup_ready_page(), add a QSpinBox between the status label and the buttons:

- Label: Optimisation patches:
- Default value: looked up from _PATCHES_PER_PAGE[(instr, paper, dd, nb)]
- Range: 50 to 1000
- Store as self._patch_count_spin

Update _update_ready_status() to keep the spinbox enabled/disabled appropriately.

### 3b. Replace _start_add_on_generation

Keep the method signature. Replace the body:

1. Validate self._install and self._install.xicclu exist.
2. pass_num = len(self._optimisation_passes) + 1
3. precond_icc = self._latest_icc_path() - validate exists.
4. pass1_ti3:
   - If self._combined_ti3s is non-empty -> self._combined_ti3s[-1]
   - Else -> self._original_pass["ti3"]
   - Validate exists.
5. target = self._pass_target_stem(pass_num)
6. target_n = self._patch_count_spin.value()
7. Go to STATE_GENERATING, clear console, show it.
8. Create a modal QProgressDialog("Generating optimisation chart...", None, 0, 5, self):
   - setWindowModality(WindowModal)
   - setAutoClose(True)
   - setAutoReset(True)
   - setCancelButton(None)  (user cannot cancel - they can't print until it is done)
9. Call pass2_generator.generate_pass2_ti1(...) synchronously with a progress_callback that updates the dialog.
10. On success: close dialog, build printtarg_args as before, launch printtarg via QProcess.
11. On exception: close dialog, show error in _gen_status and console, return to STATE_READY.

### 3c. _on_printtarg_done

No logic change. It already stores ti1, ti2, emits passChartsGenerated, loads .ti2, and transitions to STATE_MEASURE.

### 3d. Cleanup

Remove the old _on_targen_done method (no longer called). Keep _on_proc_stdout because colprof in _run_build_profile still uses it.
