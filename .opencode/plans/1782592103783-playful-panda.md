# Fix: Two-Step Wizard Ignores Persisted Device Settings

## Problem
When opening the Two-Step Profile Wizard, the instrument device and its optional flags always default to `i1Pro (i1)` instead of using the values previously saved in `QSettings`. The single-page `GeneratePage` works correctly.

## Root Cause
In `wsprofiler/ui/two_step_dialog.py`, method `_setup_generate_page()` (lines 228–329), the signal connections are wired **before** `self._restoring = True` is set. The initial call to `self._update_paper_options()` at line 284 triggers `self._paper_combo.setCurrentIndex(...)`, which emits `currentIndexChanged`. That signal is connected to `_persist_settings()`, which executes (because `_restoring` is not yet `True`) and **overwrites** the user's saved `wizard/last_*` QSettings with default values (`i1`, `Letter`, etc.). The restoration block that follows then reads those freshly-overwritten defaults.

`GeneratePage` does not have this bug because its equivalent `_on_instrument_changed()` does not touch the paper combo, and no signal that triggers `_persist_settings()` fires before `_restoring = True`.

## Files to Modify

1. `wsprofiler/ui/two_step_dialog.py`
   - Move `self._restoring = True` so it precedes the first `self._update_paper_options()` call in `_setup_generate_page()`.
   - Keep the rest of the restoration logic unchanged.

2. `wsprofiler/tests/test_session_integration.py`
   - Add a regression test that:
     1. Writes non-default device/paper/flag values to `QSettings`.
     2. Instantiates `TwoStepWizardDialog`.
     3. Asserts that the dialog widgets reflect the persisted values, not the defaults.

## Implementation Details

### Change in `two_step_dialog.py`

Current order in `_setup_generate_page()` (lines 276–310):
```python
# signal connections ...
self._update_paper_options()
self._refresh_summary()

# Restore persisted defaults (block _persist_settings while doing so)
self._restoring = True
settings = QSettings()
# ... restore device/paper/flags ...
self._restoring = False
```

Required order:
```python
# signal connections ...

# Restore persisted defaults (block _persist_settings while doing so)
self._restoring = True
self._update_paper_options()
self._refresh_summary()

settings = QSettings()
# ... restore device/paper/flags ...
self._restoring = False
```

This ensures `_persist_settings()` short-circuits during both the initial combo population and the subsequent `setCurrentIndex` calls inside the restoration block.

### Regression Test

Add a new test function (e.g., `test_two_step_dialog_restores_qsettings`) in `test_session_integration.py`:
- Use `QSettings` directly to set `wizard/last_device`, `wizard/last_paper`, `wizard/last_double_density`, `wizard/last_no_border` to non-default values (e.g., device `"CM"`, paper `"A3"`, dd `True`, nb `False`).
- Create `TwoStepWizardDialog(workspace=...)`.
- Assert `dialog._instr_combo.currentData() == "CM"`.
- Assert `dialog._paper_combo.currentData() == "A3"`.
- Assert `dialog._dd_check.isChecked() is True`.
- Assert `dialog._no_border_check.isChecked() is False`.
- Clean up QSettings keys in a `finally` block so the test is isolated.
