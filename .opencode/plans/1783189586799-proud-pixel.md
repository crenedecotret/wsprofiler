# Plan: Add Optimise subsections to sidebar

## Goal
Replace the embedded MeasurementPage approach (which looks terrible) with sidebar sub-steps under "Optimise": **Generate**, **Measure**, and **Profile**. These follow strict pipeline order with gating.

## Files to modify

| File | Changes |
|---|---|
| `wsprofiler/ui/wizard.py` | Replace `QListWidget` with `QTreeWidget`; add sub-item management; update step availability for tree items; wire sub-item clicks to OptimisePage |
| `wsprofiler/ui/pages/optimise_page.py` | Restructure internal `QStackedWidget` from 6 flat states to 3 sub-pages (Generate, Measure, Profile), each with its own stacked widget for transient states; split "done" into generate-done and profile-done; emit `subStepChanged` signal |
| `wsprofiler/ui/styles/dark.qss` | Add `QTreeWidget` styling to match current `QListWidget` look + indent sub-items |

## Architecture

### Sidebar: `QListWidget` → `QTreeWidget`

The Wizard sidebar changes from a flat `QListWidget` to a `QTreeWidget`:

```
Generate          (main item)
Measure           (main item)
Profile           (main item)
Optimise          (main item, always expanded)
  ├─ Generate     (sub-item, indented)
  ├─ Measure      (sub-item, indented)
  └─ Profile      (sub-item, indented)
```

**Navigation signal**: Use `QTreeWidget.currentItemChanged` (fires on both user clicks AND programmatic `setCurrentItem` calls). This preserves the existing behavior where `_on_step_changed` fires for programmatic navigation (e.g., `setCurrentRow` after chart generation completes). The existing 12+ call sites that programmatically advance the wizard (`_on_chart_generated`, `_on_measurements_complete`, `_on_profile_generated`, `_on_load_session_clicked`, `load_wsp_session`, etc.) will continue to work.

**Sub-item expand arrows**: Use `QTreeWidget.setItemsExpandable(False)` globally to suppress all expand/collapse arrows. The "Optimise" parent is always expanded via `item.setExpanded(True)`.

**Index mapping**: Maintain `_prev_step_index` as the **stack index** (0-3), not the tree item index. A helper `_tree_item_to_stack_index(item)` resolves tree items to stack indices:
- Main items: map directly to their stack position (Generate=0, Measure=1, Profile=2, Optimise=3)
- Sub-items: always map to stack index 3 (Optimise)

When a sub-item is clicked, the stack stays at index 3 (Optimise page), and `OptimisePage.go_to_substep()` is called to switch the internal sub-page.

### OptimisePage: 3 sub-pages with internal stacks

Replace the current 6-state flat `QStackedWidget` with 3 sub-pages, each containing its own `QStackedWidget` for transient states:

**Sub-page 0: Generate**
Internal stacked widget (`_gen_stack`):
- `GEN_READY` (0): Chart config form + "Generate Add-on Chart" button + status label
- `GEN_GENERATING` (1): "Generating add-on chart…" spinner
- `GEN_DONE` (2): "Chart generated! Ready to measure." + "Measure" button

**Sub-page 1: Measure**
The `MeasurementPage` widget directly (no internal stack needed).

**Sub-page 2: Profile**
Internal stacked widget (`_prof_stack`):
- `PROF_READY` (0): Profile settings (gamut, quality, smoothing, description) + "Build Optimised Profile" button
- `PROF_BUILDING` (1): "Building optimised profile…" spinner
- `PROF_DONE` (2): "Optimisation complete!" + ICC path + "Optimise Again" button

The top-level `_stack` (`QStackedWidget`) holds these 3 sub-pages.

**Console management**: A single shared `LogConsole` instance remains at the OptimisePage root level (not inside any sub-page). Its visibility is toggled by the "Show output" checkbox, which is shown/hidden based on the current sub-state (visible during GEN_GENERATING, PROF_BUILDING; hidden otherwise). The `_on_proc_stdout` method continues to write to the same `self._console` reference regardless of which sub-page is active.

### Signals

New signal on OptimisePage:
```python
subStepChanged = Signal(int)  # emits 0, 1, or 2 when sub-page changes
```

The Wizard connects to this in `__init__` (after page construction):
```python
self._pages["Optimise"].subStepChanged.connect(self._on_optimise_substep_changed)
```

`_on_optimise_substep_changed(idx)` highlights the corresponding sub-item in the tree by calling `self.steps.setCurrentItem(sub_item)`.

### State transitions

| Trigger | From | To | Sub-step |
|---|---|---|---|
| `set_original_pass_data()` / `load_wsp_session()` | any | GEN_READY | Generate (0) |
| "Generate Add-on Chart" clicked | GEN_READY | GEN_GENERATING | Generate (0) |
| printtarg fails | GEN_GENERATING | GEN_READY | Generate (0) |
| printtarg succeeds | GEN_GENERATING | GEN_DONE | Generate (0) |
| "Measure" button (on GEN_DONE) | GEN_DONE | MeasurementPage | Measure (1) |
| `measurementsComplete` signal | Measure | PROF_READY | Profile (2) |
| "Build Optimised Profile" clicked | PROF_READY | PROF_BUILDING | Profile (2) |
| colprof fails | PROF_BUILDING | PROF_READY | Profile (2) |
| colprof succeeds | PROF_BUILDING | PROF_DONE | Profile (2) |
| "Optimise Again" clicked | PROF_DONE | GEN_READY | Generate (0) |

### Sub-step gating (Wizard-managed)

The Wizard's `_update_step_availability()` is extended to also manage sub-item enablement:
- Optimise > Generate: always enabled when Optimise parent is available
- Optimise > Measure: enabled when `OptimisePage.can_measure()` returns True
- Optimise > Profile: enabled when `OptimisePage.can_build_profile()` returns True

**`can_measure()` implementation**: Returns `True` if `_optimisation_passes` is non-empty and the latest pass has a non-None `ti2` value that exists on disk. This covers the case after `_on_printtarg_done` succeeds.

**`can_build_profile()` implementation**: Returns `True` if `_optimisation_passes` is non-empty and the latest pass has a non-None `ti3` value that exists on disk. This covers the case after `_on_measurements_complete` fires.

### Default sub-step when "Optimise" is selected

When the user navigates to Optimise (via click or programmatic `setCurrentRow(3)`):
1. The Wizard calls `_refresh_page_for_step(3)` as usual
2. `_refresh_page_for_step` detects the Optimise page and calls `OptimisePage.go_to_substep()` with the appropriate default:
   - If no passes yet → `SUB_GENERATE`
   - If passes exist but latest has no ti3 → `SUB_GENERATE` (show GEN_DONE or GEN_READY)
   - If latest pass has ti3 but no icc → `SUB_PROFILE`
   - If latest pass has icc → `SUB_PROFILE` (show PROF_DONE)
3. OptimisePage emits `subStepChanged` which syncs the sidebar highlight

### 1. `wizard.py` — Sidebar refactor

**Imports** (line 7-16): Replace `QListWidget`/`QListWidgetItem` with `QTreeWidget`/`QTreeWidgetItem`.

**Sidebar construction** (lines 61-66): Replace `QListWidget` with `QTreeWidget`:

**Page registration** (lines 81-90): Create tree items with sub-items:
```python
self._tree_items = {}  # map (main, sub) or (main,) → QTreeWidgetItem
for title, page in self._pages.items():
    item = QTreeWidgetItem(self.steps, [title])
    self.stack.addWidget(page)
    if title == "Optimise":
        for sub_title in ("Generate", "Measure", "Profile"):
            sub_item = QTreeWidgetItem(item, [sub_title])
            self._tree_items[("Optimise", sub_title)] = sub_item
        item.setExpanded(True)
    self._tree_items[(title,)] = item
```

**Signal** (line 92): Replace `currentRowChanged` with `currentItemChanged`:
```python
self.steps.currentItemChanged.connect(self._on_current_item_changed)
```

**`_on_current_item_changed`** (replaces `_on_step_changed`): Resolves the tree item to a stack index via `_tree_item_to_stack_index()`. For sub-items, calls `OptimisePage.go_to_substep(idx)` after switching the stack. Keeps `_prev_step_index` as the stack index.

**`_tree_item_to_stack_index`**: Returns 0-3 for main items, 3 for all sub-items (they belong to the Optimise page).

**`_update_step_availability`** (lines 739-794): Update to use `QTreeWidgetItem` instead of `QListWidgetItem`. Access items via `self._tree_items[(title,)]` instead of `self.steps.item(i)`. Add sub-item gating:
```python
opt_generate = self._tree_items.get(("Optimise", "Generate"))
opt_measure = self._tree_items.get(("Optimise", "Measure"))
opt_profile = self._tree_items.get(("Optimise", "Profile"))
if opt_generate:
    self._set_item_enabled(opt_generate, optimise_available)
if opt_measure:
    self._set_item_enabled(opt_measure, optimise_available and opt_page.can_measure())
if opt_profile:
    self._set_item_enabled(opt_profile, optimise_available and opt_page.can_build_profile())
```

**`_refresh_page_for_step`** (lines 710-723): Add handling for when index is 3 (Optimise). Call `OptimisePage.go_to_default_substep()` which determines the appropriate sub-step based on pass data state.

**`_on_optimise_substep_changed`**: New handler that selects the corresponding sub-item in the tree:
```python
def _on_optimise_substep_changed(self, sub_idx: int) -> None:
    sub_titles = ("Generate", "Measure", "Profile")
    item = self._tree_items.get(("Optimise", sub_titles[sub_idx]))
    if item:
        self.steps.setCurrentItem(item)
```

**Add public methods**:

- Hide during `GEN_READY`, `GEN_DONE`, `PROF_READY`, `PROF_DONE`, `SUB_MEASURE`

- `_start_add_on_generation`: `_gen_stack.setCurrentIndex(GEN_GENERATING)`, show console
