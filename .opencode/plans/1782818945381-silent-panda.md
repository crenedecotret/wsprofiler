# Plan: Gate sidebar step availability on completion / loaded session

## Goal
Make the Measure, Profile, and Optimise sidebar steps unavailable (disabled) until the previous step has been completed, OR until a session has been loaded from a `.wsp` file.

## Context
- The Wizard uses a `QListWidget` sidebar (`self.steps`) with 4 items: Generate, Measure, Profile, Optimise.
- Currently all items are always enabled; users can click ahead to any step at any time.
- Step completion is tracked implicitly by file existence in the session temp dir:
  - Generate complete → `.ti2` exists
  - Measure complete → `.ti3` exists
  - Profile complete → `.icc` exists
- `SessionManager.is_loaded` indicates whether a `.wsp` session was loaded.
- `load_wsp_session()` already restores files and jumps to the furthest completed step.

## Approach
Add a `_update_step_availability()` method to `Wizard` that enables/disables each sidebar `QListWidgetItem` based on whether the prerequisite files exist. Call it after every state change (init, chart generated, measurements complete, profile generated, session loaded).

Disabled items will still be selectable **programmatically** (so the wizard can auto-advance), but users cannot click them.

## Files to Modify

### 1. `wsprofiler/ui/wizard.py`
- **Import**: add `Qt` to the `PySide6.QtCore` imports.
- **New helper**: `_set_item_enabled(item: QListWidgetItem, enabled: bool)` to safely toggle `Qt.ItemIsEnabled` while preserving other flags.
- **New method**: `_update_step_availability()`
  - Generate: always enabled.
  - Measure: enabled if `self._pending_ti2 is not None`, or `session.target_path.with_suffix(".ti2").exists()`.
  - Profile: enabled if `self._pages["Measure"].get_current_ti3_path()` returns a path.
  - Optimise: enabled if `session.target_path.with_suffix(".icc").exists()`, or `self._pages["Optimise"].has_data()`.
  - Set a tooltip on disabled items (e.g. "Complete measurements first").
- **Call sites**:
  - End of `__init__` (after `_initialise_session()`).
  - End of `_on_chart_generated()`.
  - End of `_on_measurements_complete()`.
  - End of `_on_profile_generated()`.
  - End of `load_wsp_session()`.

### 2. `wsprofiler/tests/test_wizard_integration.py`
- Update `_wizard_with_suppressed_dialogs` (the manual-construction branch when `dest is not None`) to call `_update_step_availability()` after `_initialise_session()`, mirroring the real `__init__`.
- Add new tests:
  - `test_wizard_fresh_only_generate_enabled` — assert only Generate item is enabled.
  - `test_wizard_measure_enabled_after_chart` — after `_on_chart_generated`, Measure is enabled.
  - `test_wizard_profile_enabled_after_measure` — after `_on_measurements_complete`, Profile is enabled.
  - `test_wizard_optimise_enabled_after_profile` — after `_on_profile_generated`, Optimise is enabled.
  - `test_wizard_load_session_enables_appropriate_steps` — load a WSP with only `.ti3` and assert Measure & Profile enabled, Optimise disabled.

2. Run new tests — all new tests must pass.
3. Manual smoke test (optional): start the app, confirm only Generate is clickable; generate a chart, confirm Measure becomes clickable; etc.
